# AQUASOLVE — COMPLETE MASTER SOFTWARE DEVELOPMENT PROMPT

## ROLE AND OBJECTIVE

Act as a senior full-stack software engineer, UI/UX designer, environmental chemistry specialist, software architect, database engineer, QA tester, and deployment engineer.

Your responsibility is to design, develop, test, and deploy a complete, modern, interactive web application named **AquaSolve — An Interactive Environmental Chemistry-Based Water Quality Analysis and Treatment Recommendation System**.

This must be a genuinely functional, end-to-end software application, not a static website, presentation, mockup, or basic water-quality calculator.

The application must transform water-quality measurements into meaningful analysis, chemistry-based explanations, treatment recommendations, interactive treatment simulations, and downloadable reports.

The central workflow is:

**Enter Water Data → Validate → Analyze → Diagnose → Explain Chemistry → Recommend Treatment → Simulate Treatment → Compare Results → Generate Report**

Build the entire application using clean, maintainable, modular, production-oriented code.

The project is an educational and preliminary decision-support system. It must never claim that simulated treatment results certify water as safe for drinking.

# 10. TREATMENT SIMULATION ENGINE

Develop a backend simulator that estimates the effect of selected treatment stages on supported water-quality parameters.

### Inputs

- Original measurements
- Selected treatment sequence
- Documented simulation assumptions
- Applicable treatment parameters

### Outputs

- Estimated values after each stage
- Final simulated measurements
- Changes from baseline
- Unresolved concerns
- Simulation warnings
- Assumptions and model limitations

### Simplified concentration model

For an eligible contaminant and treatment process, a basic illustrative model may be:

`C_after = C_before × (1 - removal_fraction)`

Use this equation only where such a model is scientifically appropriate.

Do not use the same removal percentage for every contaminant or treatment.

Do not apply percentage-removal models blindly to pH, dissolved oxygen, or parameters requiring different chemical relationships.

### Scientific requirements

- Store model assumptions separately from the application code.
- Associate efficiencies with specific contaminants and treatment methods.
- Document sources for each efficiency.
- Allow uncertainty or efficiency ranges where appropriate.
- Handle unsupported treatment-parameter combinations explicitly.
- Avoid generating negative concentrations.
- Respect stage order and prerequisites.
- Clearly distinguish measured and simulated values.

Do not fabricate scientifically validated efficiencies.

If validated coefficients are unavailable, use clearly labeled illustrative assumptions only in demonstration mode.

### API

`POST /api/simulate`
